# 调研与取舍（2026-11-23）

没有找到「微信反馈 → QQ 机器人 → 反馈库」的现成项目，因此借鉴各家做法自建。

## QQ 怎么接

| 方案 | 结论 |
|---|---|
| **QQ 官方机器人 API + WebSocket** | **采用**。免费、合规、不需要公网 IP |
| 官方 API + Webhook | 需要公网 HTTPS 回调地址，部署更重 |
| NapCat（GitHub 约 1.3 万星）/ Lagrange（约 3 千星）等协议端 | 模拟登录个人号，违反 QQ 用户协议，有封号风险。不采用 |

以官方文档为准核对到的规则（网上不少资料已过时）：

- 接口域名已统一为 `api.bot.qq.com`（2026-08）。已实测可连通，错误码与文档一致。
- 单聊被动回复：60 分钟内、每条消息最多 4 次（同一接口文档的 msg_id 字段说明里仍写 5 分钟，属文档不一致）。本系统通常几秒内回复，两种口径都满足。
- 消息事件带图片、文件、语音（含转写 `asr_refer_text`）、引用（`ref_msg_idx`）、聊天记录（`message_type=102`）。
- 相同消息可能重复推送，需用 `msg_idx` 去重。
- WebSocket 断开后短时间内重连会补发遗漏事件；具体时限官方未写明。

来源：[单聊消息事件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/c2c_message_create.html) · [发送单聊消息](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html) · [消息收发概述](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html) · [WebSocket](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/event-emit/websocket.html) · [变更记录](https://bot.q.qq.com/wiki/develop/api-v2/changelog.html)

**为什么没直接用腾讯官方 Node SDK**（[qqbot-nodejs](https://github.com/tencent-connect/qqbot-nodejs) 1.0.5）：读源码发现它收到消息先保存进度再处理，两者之间崩溃会丢消息；也不检测心跳超时，网络假死时不会重连。本项目按官方协议自己实现了网关，这两点都有测试覆盖。

| 项目 | 借鉴 | 为什么不直接用 |

| [ticketgram](https://github.com/mikurei/ticketgram)、[telegram-feedback-bot-topics](https://github.com/MasterGroosha/telegram-feedback-bot-topics) | 机器人收单的交互 | Telegram 专用 |

## OCR

用同一张仿微信截图实测：tesseract.js 漏掉整条绿色气泡，字间插空格；PP-OCRv6 tiny 文字全对（仅漏一个右引号），约 0.2 秒，模型 6.4MB。采用后者，模型随仓库分发。

## 另一条路：微信官方 ClawBot（iLink）

2026 年微信推出了官方机器人能力，理论上可在微信内直接转发。但目前公开资料多为第三方，提到仍在灰度、腾讯可随时终止。暂不采用；收录逻辑与 QQ 接入是分开的，以后成熟了可以加一个接入渠道。
